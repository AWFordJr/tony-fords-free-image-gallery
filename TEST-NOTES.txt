NOTES
-----
On php -S the installer sets pretty_urls to 0 (existing installer behavior
for the built-in server). Pretty paths still work when requested through
router.php; generated links use /index.php?r=… form (e.g.
/index.php?r=image%2F1-tony-ford-sample-1-0-1). Apache/nginx installs should
still get pretty URLs when the installer allows them.

This retest did not repeat the full v1.0.0 ~100-check security sweep
(SQLi/XSS/CSRF/upload exploits, login throttling, etc.). Those passed on
v1.0.0; this pass focused on the v1.0.1 changes and a fresh install /
login / upload / albums / About / footer / version / helper / theme check
in both gallery modes, with zero PHP warnings and zero Chromium console
errors.

After these tests, config.php, the locked installer, and the test uploads
were removed from the tree, and install.php was put back, so v1.0.1 can be
installed fresh. The local test databases were left on the box and are not
part of this package.
